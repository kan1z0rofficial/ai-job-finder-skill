# Скилл: Поиск работы (ai-job-finder-skill)

Универсальный скилл для AI-агентов (Claude, Codex, GPT, OpenClaw и совместимых).
Активируй, когда пользователь просит найти работу, вакансии, хочет оценить рынок труда по своей профессии.

## 1. Параметры поиска

Собери у пользователя следующие параметры. Если пользователь уже указал профессию, город и формат — сразу переходи к поиску, недостающие необязательные параметры помечай как «не указано».

| Параметр | Обязательность | Варианты / пример |
|---|---|---|
| Профессия / должность | обязательный | «сварщик», «бухгалтер», «Python-разработчик» (допускается несколько) |
| Город | обязательный | «Екатеринбург» или «удалённо по РФ» |
| Формат работы | обязательный | офис / удалённо / гибрид / вахта / сменный график |
| Опыт работы | необязательный | без опыта / 1–3 года / 3–6 лет / более 6 лет |
| Зарплата (от–до) | необязательный | «от 80 000 до 150 000 руб» |
| График | необязательный | 5/2, 2/2, посменно и т.п. |
| Исключить слова | необязательный | «без продаж», «не аутсорс» |

Если обязательного параметра не хватает — задай **один** уточняющий вопрос и перечисли в нём все недостающие параметры сразу (не дожимай по одному).
Для формата «удалённо» город не обязателен: считай, что поиск идёт по РФ, если пользователь не назвал страну или город.

## 2. Где искать (источники)

Приоритетный порядок:

1. **hh.ru** — офисные и удалённые вакансии по всей стране.
2. **Rabota.ru** — регионы, производственные специальности.
3. **SuperJob** — дополнительный источник.
4. **Авито Работа** — рабочие специальности, вахта, сменные графики.

Способ поиска: веб-поиск с актуальной датой. Формат запроса:
`{профессия} {город} вакансии {год} {формат}`

Если у агента есть инструмент открытия URL — открывай страницы вакансий и читай детали (зарплата, опыт, график) из первоисточника, а не только из сниппетов поисковика.

Если в окружении доступны файлы репозитория, используй их:

- `references/sources.md` — параметры URL, area-id и правила фильтрации по источникам;
- `references/output.md` — схема JSON и правила CSV-вывода;
- `scripts/hh_url.py` — сборка ссылки hh.ru без ручного угадывания параметров, например:
  `python scripts/hh_url.py --text "сварщик" --area "Тюмень" --schedule fly-in-fly-out`;
- `scripts/format_results.py` — конвертация результатов в CSV, Markdown или JSON.

Если скилл загружен одним файлом (Claude Projects, Custom GPT, вставка в системный промпт) — работай по инструкциям ниже, а ссылки строй через обычный веб-поиск.

## 3. Формат ответа

Таблица результатов, отсортированная по релевантности, максимум 10 вакансий:

| # | Должность | Компания | Зарплата | Опыт | Город / формат | Источник |
|---|---|---|---|---|---|---|

После таблицы:

- **Итог:** сколько вакансий найдено всего, медианная зарплата по выборке (если зарплаты указаны), дата поиска.
- **Совет:** 1–2 конкретных предложения, как улучшить поиск (другие формулировки должности, соседние города, смежные профессии).

Если вакансий не найдено — честно сообщи об этом, предложи ослабить фильтры и дай 2–3 альтернативных поисковых запроса.

### Машинный формат

Если пользователь просит JSON, CSV или данные для таблицы/скрипта — отдай результат по схеме из `references/output.md`. При доступе к shell используй:

```bash
python scripts/format_results.py --input results.json --format csv
```

Не меняй названия полей и не подставляй выдуманные значения: отсутствующая зарплата — `null`, а не `0`.

## 4. Правила

- Не выдумывай вакансии, зарплаты, компании и ссылки — только данные из найденных источников.
- Всегда указывай дату поиска в формате `ГГГГ-ММ-ДД` (рынок вакансий меняется быстро).
- Если зарплата не указана — пиши «не указана», не подставляй оценку.
- При формате «вахта» отдельно отмечай длительность вахты и ритм ротаций, если указаны.
- Не запрашивай и не отправляй личные данные пользователя (ФИО, телефон, резюме) никуда — только публичный поиск вакансий.
- Если пользователь просит «подать заявку» или «откликнуться» — отклоняй: скилл только ищет и показывает вакансии, не совершает действий от имени пользователя.
- Дубли одной вакансии на разных площадках показывай один раз, перечисляя источники через запятую.

## 5. Примеры диалога

**Пользователь:** «Ищу работу сварщиком в Тюмени»
→ Профессия и город есть. Уточни одним сообщением: «Уточните, пожалуйста: 1) формат работы — офис/вахта/смены? 2) ваш опыт?»

**Пользователь:** «Python-разработчик, удалённо, опыт 3 года, от 200к»
→ Все параметры есть, кроме города. Для удалёнки город не обязателен — сразу ищи: `Python-разработчик удалённо вакансии 2026 опыт 3 года`.

**Пользователь:** «Найди вакансии и откликнись за меня»
→ Откажись от откликов и предложи только список вакансий со ссылками.

## 6. Установка в агентах (кратко)

- **Claude Code (плагин):** `/plugin marketplace add kan1z0rofficial/ai-job-finder-skill`, затем `/plugin install ai-job-finder-skill@ai-job-finder`.
- **Claude Code (вручную):** скопируй `SKILL.md` в `~/.claude/skills/ai-job-finder-skill/` (или `.claude/skills/ai-job-finder-skill/` в проекте).
- **Claude Projects (claude.ai):** загрузи `SKILL.md` в Project knowledge.
- **OpenClaw / OpenClaw-совместимые:** помести папку `ai-job-finder-skill/` с `SKILL.md` в директорию скиллов агента (по умолчанию `~/.openclaw/skills/` или путь из конфигурации `skills.dir`).
- **Codex / GPT (ChatGPT):** вставь содержимое `SKILL.md` в системные инструкции — для Codex это `AGENTS.md` в корне проекта, для GPT — поле Instructions у Custom GPT.
- **Kimi и другие агенты с поддержкой скиллов:** любая папка с `SKILL.md` в директории скиллов; агент без поддержки скиллов — просто вставь файл в системный промпт.

Подробная инструкция по каждой системе — в `INSTALL.md` репозитория.
